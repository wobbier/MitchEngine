# Terrain

> Verified against engine commit `ed08c80a` plus the optional look-ahead and window-retirement changes, 2026-10-20.

The terrain system loads a fully resident tiled heightfield into one `Terrain` scene component, renders internal patches through the ordinary lit mesh path, and provides static triangle-mesh collision at canonical sample resolution. The `TerrainData` library supplies signed addressing, shared-border edits, normals and queries, patch geometry, source/cooked serialization, brush strokes and source publication. Havana provides a terrain authoring panel with four sculpting tools, four-layer surface painting, RAW heightmap exchange and recovery snapshots. Runtime patches select stitched LODs from camera pixel error. Version 2 cooked assets add bounded detail streaming over resident coarse coverage; version 3 streams the coverage window too. Version 4 adds painted surface pages and layer settings.

## Overview

A `Heightfield` owns validated `Settings` and a map of resident tiles. Each tile stores `(TileQuads + 1)²` Float32 elevations, including copies of shared edges. Integer sample coordinates describe one terrain-wide X/Z lattice; sample spacing converts that lattice to metres. Y is elevation in metres.

`Settings` defaults to 256 quads per storage tile, 64 quads per render patch, 1 m sample spacing, and one tile. Tile and patch sizes must be powers of two, with patch size at most tile size. Tile size is capped at 4096 quads and patch size at 1024 to bound individual allocations. Dataset tile coordinates are signed 32-bit; sample coordinates are signed 64-bit.

## How It Works

### Resident scene integration

Add a `Terrain` component to an entity with a `Transform` and choose a `.terrain` manifest or `.terrainc` cooked package. The asset browser recognizes both as Terrain assets. Reflected fields cover the asset reference, base color, roughness, shadow casting, collision, friction, and restitution. Scene and prefab serialization stores those settings, not height arrays or generated children.

`TerrainResource::LoadAsync` reads and validates the asset and source pages, then prepares `ResidentTerrain` CPU geometry on a resource loader thread. `FinishAsyncLoad` publishes one immutable snapshot. `ResourceCache` shares the resource between instances; render and physics adapters retain snapshot references independently. When a `.meta` GUID exists, it supplies the runtime asset identity; standalone loads use the GUID embedded in the manifest/package. Metadata is pass-through and does not invoke the texture/model importers.

`TerrainCore` is engine-owned and explicitly registered/scheduled by `Engine`. It validates the final world matrix, including parents: translation is supported, rotation and scaling are rejected, and terrain cannot belong to a dynamic/kinematic rigidbody. Errors appear in the component inspector. **Reload Terrain** retries a file load asynchronously, including a previously failed load.

At play start, required collision assets are completed before `PhysicsCore` starts. Each physics synchronization refreshes terrain readiness. If required terrain is missing, invalid, or failed, 3D physics stepping waits while its error remains inspectable; repairing the source and reloading it resumes physics. Resident assets use this barrier during scene preparation. Version 2 streamed assets also apply it to required collision pages during travel, as described below. Terrain with collision disabled does not impose that barrier.

`RenderCore` creates internal `MeshData` and mesh instances from the prepared patches, using `TerrainMaterial` and the component's color/roughness when the source has no surface palette. Painted sources blend their own layer colors/roughness. Patches share the owning terrain entity's selection ID and use the same visibility-index allocation as ordinary meshes/models. Each patch owns its material instance because material preparation runs in parallel jobs. Terrain bounds participate in editor selection bounds and Frame Selected. Render preparation now runs after resource finalization and camera late updates, so culling uses the current camera snapshot.

Terrain chooses a common stitched topology for all camera and shadow passes (see Runtime LODs below). Camera culling does not remove off-camera shadow casters. On replacement, disable, removal, scene unload, or Play/Stop, the render bridge removes command references before releasing GPU geometry. No patch becomes a scene entity.

The GPU picking pass uses the camera's visible ray segment rather than a fixed 100 m range. Framing a large terrain can therefore move the editor camera beyond 100 m while its rendered patches remain selectable.

`PhysicsCore` builds one static mesh shape per storage tile, with the same canonical triangle split as height queries. Cache entries retain immutable terrain snapshots and can serve multiple instances. Collision has no dependency on GPU mesh buffers or visual culling. Replacement collision meshes are prepared before live shapes are removed; inactive/removed instances release their shapes and unused cache entries. Entity layers and the project collision matrix apply to terrain queries/contacts.

### Residency, borders, and editing

`LoadTile` validates sample count, finite elevations, and exact agreement with resident neighboring edge/corner copies before replacing any data. `CreateFlatTile` uses the same path. `UnloadTile` removes a tile; `SetPending` records an outstanding request for a nonresident tile without performing I/O.

`Settings::Owner` chooses the positive-side tile at a shared boundary and the last tile at the finite outer boundary. It uses `FloorDivide`, so negative positions follow the same rule as positive positions. `GetSample` reads the owner and reports `Ready`, `Pending`, `Unavailable`, or `OutsideBounds`; it does not fall back to a possibly stale shared copy.

`SetSample` requires every tile sharing the sample to be resident, then changes all copies together. It increments the heightfield revision once and marks intersecting tile-local `DirtySamples`, expanded by one sample for vertex normals. The same revision propagates to affected neighboring normal strips even when their heights do not change. Repeating an unchanged edit does not increment the revision. `ClearDirty` clears rectangles without changing content revisions.

### Queries and geometry

`Query` takes terrain-local X/Z in metres. It rejects non-finite inputs as `InvalidInput` and never loads missing data. Each quad uses triangles `(a, c, b)` and `(b, c, d)`, where `a/b/c/d` are its low-X/low-Z, high-X/low-Z, low-X/high-Z, and high-X/high-Z corners. Height interpolation and the returned geometric normal follow that split; a saddle therefore differs from bilinear interpolation.

`GetNormal` computes a smooth vertex normal using adjacent height samples. It uses central differences internally and one-sided differences at the finite outer boundary. Missing owner/halo data returns a query status rather than manufacturing a normal.

`BuildPatch` reads an immutable heightfield snapshot and creates patch-local positions, smooth normals, normalized UVs, bounds, and triangle index lists. `SampleOrigin` preserves the integer terrain location independently of Float32 local vertex positions. Levels use strides 1, 2, 4, … through the patch size over one full-resolution vertex array.

`PatchLod::MaxError` conservatively bounds vertical deviation from the fine triangle surface. The nested diagonals align, so the maximum of the piecewise linear difference occurs at a fine-grid vertex. Errors are rounded upward when conversion to Float32 would otherwise underestimate them. `PatchMesh::Revision` identifies the heightfield snapshot used to build it.

### Runtime LODs

`Terrain::LodPixelError` defaults to 2 pixels, and `LodHysteresis` defaults to 0.2. Both serialize with the component and are editable in the inspector. For each resident patch, `SelectTerrainLods` chooses the coarsest power-of-two stride whose geometric error fits the budget. Coarsening waits until the error falls below `(1 - hysteresis) * budget`; refinement uses the full budget. Regular errors use a monotone envelope of `PatchLod::MaxError`.

Every rendering camera with a positive output size participates, including World View in editor builds. Projection diagonals and actual output dimensions provide pixels per metre. Perspective bounds include both image-plane motion and depth changes caused by vertical displacement; orthographic views use their constant scale. Selection combines camera demands into one conservative result, then refines neighbors to keep adjacent strides within 2:1 across patch and signed tile boundaries. Off-camera patches remain available to shadows.

The finer patch collapses alternate boundary samples onto its coarser neighbor. All sixteen edge masks handle corners without skirts. Each stitched triangle lies inside one next-coarser regular triangle; twice that level's error bounds the stitched surface against canonical heights. Neighbor refinement also enforces this extra transition error within the pixel budget. Forward, shadow, picking and wireframe passes read the selected index topology through `MeshData`; they share vertices, canonical normals and one choice per patch. Collision and source queries never switch levels.

`RenderCore` shares index patterns by patch resolution, level and edge mask across instances. It creates a pattern when first requested and retires unused patterns after all instances update. Visual changes preserve patch vertex buffers and collision cooks. Invalid settings or failed topology upload fall back to uniform full detail for the whole instance; upload failures back off before retrying, and the Inspect panel displays the error.

In **Terrain > Inspect**, **Patches** outlines patch bounds and **LODs** colors levels 0–5 green, yellow, orange, blue, purple and pink (repeating for higher levels). Counts cover the entire resident instance, including off-camera patches. **Force level** uses -1 for automatic selection and clamps other values to the available levels. Forced levels bypass the pixel budget. Forced levels and debug flags are transient and do not serialize; the global imported-mesh `--lod-bias` does not affect terrain.

`Tests/Source/TerrainLodTests.cpp` covers all edge masks at multiple resolutions/strides, corner coverage, winding, matching boundary steps, nested diagonals, signed cross-tile neighbors, projection error bounds, perspective/orthographic demand and hysteresis. The game fixture `../Assets/Scenes/Tests/TerrainLodFlows.edscript` clicks the actual Inspect buttons, captures colored/wireframe levels, checks multi-camera refinement and forced levels, verifies stable vertex buffers/collision cooks, saves a runtime scene and exercises Play/Stop.

### Source formats

`SerializeManifest` / `DeserializeManifest` encode a version 1 JSON manifest with `Format: MitchTerrain`, a nonzero sixteen-digit hexadecimal `AssetGUID`, validated settings, and one page reference per declared tile. References use unique forward-slash relative paths; parent traversal and absolute paths are rejected. Serialization sorts pages by X then Z for deterministic output.

`SerializePage` / `DeserializePage` encode source pages explicitly in little endian:

| Field | Encoding |
| --- | --- |
| Magic / version | `MTHP`, UInt32 version 1 |
| Dimensions / coordinates | UInt32 tile quads, Int32 tile X and Z |
| Payload metadata | UInt64 byte length and FNV-1a checksum |
| Payload | Row-major IEEE-754 Float32 elevations |

Page readers validate settings, coordinates, exact length, checksum, and finite samples before publishing their output. The caller passes a decoded page to `LoadTile` to validate shared borders.

### Cooked format

`CookHeightfield` requires every source tile. It produces a version 1 `MTRN` package with an 88-byte header, a 40-byte directory record per tile, and independently checksummed payloads. Header and directory checksums cover their respective metadata. All integers and Float32 bit patterns are written explicitly in little endian, without raw structure serialization.

The header records settings, encoding, asset GUID, tile count, and a source hash. Source hashing includes the cooker version, encoding, settings, coordinates, and Float32 source samples. Each directory entry records coordinates, absolute byte offset, payload byte length, checksum, and decoded minimum/maximum elevation. Directory records and payloads are ordered by tile X then Z.

Float32 cooking preserves source height bits. UInt16 cooking uses the asset-wide `HeightBase` / `HeightRange`, rounds to the nearest encoded sample, and rejects out-of-range heights rather than clamping. `CookInfo::QuantizationErrorBound` includes half an encoding step plus a conservative allowance for Float32 decode rounding; Float32 cooking reports zero.

`ReadCookedHeightfield` checks header/directory integrity, dimensions, counts, ordered coordinates, offsets, lengths, tile checksums, finite heights, decoded bounds, and shared borders. It constructs a temporary heightfield and publishes it only when the entire package passes validation. Loaded cooked tiles start with clean dirty rectangles. All codec APIs preserve output arguments on failure and return an error string.

## How to Extend

Use the pure data headers without renderer or editor headers. Capture a `Heightfield` copy before launching worker work; mutations of the same instance are not thread safe. After building a patch, compare its revision with the current source revision before publishing derived results. `BuildResidentTerrain` prepares a complete immutable snapshot for `Terrain::SetData`, which also supports procedural CPU input without adding scene children.

The focused test filter is `--test-case=Terrain*` on `MitchEngine_Tests`. The source and cooked codecs work on buffers; callers supply disk I/O and publication behavior.

## Caveats & Fragility

- Source-page edits outside the editor do not automatically reload manifests; use **Reload Terrain**. Automatic cooking and source-generation compaction remain planned.
- Patch builds require owner samples and normal halos to be resident. Canonical height queries and collision remain at full sample resolution while visual topology coarsens.
- Within a loaded representation, index LOD changes reduce submitted triangles. Version 2 eviction releases detail vertex buffers and their CPU copies; its coverage and patch count stay resident. Version 3 also releases coverage pages and bounds rendered patch counts to an admitted visual window.
- Selection is deliberately conservative for bounds touching/behind a camera's near plane, oblique projections and invalid view data. Such views retain full detail; opposed cameras can therefore reduce the triangle savings. No geomorphing is implemented, so discrete transitions can pop.
- Version 1 cooked blocks contain complete tiles at one encoding. Version 1 decoding remains eager; versions 2/3 stream independent Float32 blocks with per-asset ceilings, world-wide CPU/GPU/collision allowances and bounded patch uploads.
- Four-layer textured PBR surfaces and canonical navigation sources are implemented. C# terrain bindings remain planned.
- Required terrain load failure holds 3D physics stepping; other gameplay/script updates continue.
- Authoring still deep-copies canonical heights for immutable snapshots. Unchanged patch/collision arrays and cooked shapes are shared; incremental authoring preparation runs on an owned document worker; source copying remains on the editor thread.

## Editor authoring

Open **View > Terrain**, use the command palette's **New Terrain...** / **Open Terrain...**, double-click a `.terrain` in the asset browser, or use **Edit Terrain** on a component. New Terrain creates a saved flat source asset with configurable tile counts, quads per tile, spacing and starting height. **Place in Scene** adds one undoable terrain instance and frames it. The creation dialog caps source data at one million stored samples; terrain rendering still retains all patches and full-resolution vertex buffers.

The panel has six workspaces: **Sculpt**, **Paint**, **Tiles**, **Foliage**, **Splines** and **Inspect**. Sculpt implements **Raise**, **Lower**, **Smooth** and **Flatten**. The Tiles workspace also implements RAW heightmap import/export. **Make Unique** in Asset & Build copies the active heights to a separate source asset and rebinds only the selected instance. Inspect implements **Patches** and **LODs**, with per-level patch counts, stitched counts, triangle totals and a forced-level slider for the selected instance. The Foliage workspace now paints scene-owned static model instances; see [Foliage authoring](Foliage.md). Remaining disabled tools have explanatory tooltips for erosion, tile resizing, dense grass, masks, roads and further diagnostics. **Cook** / **Build** publish streamed runtime terrain, **Residency** shows detail versus coarse coverage, and **Budgets** opens Project Settings (Terrain tab). **Asset & Build** contains save/revert controls and the planned asset operations. Icons come from `Assets/Icons/outline/` through the shared `EditorIcons` helper (`Modules/Havana/Source/Utils/EditorIcons.h`), which rasterizes each SVG at its drawn size into a theme-tinted texture and releases them all when the editor shuts down.

Select a terrain instance, open its source document, then select a sculpt tool or enable the brush. Drag in World View to sculpt. The outer ring marks radius; the inner ring marks the fully weighted center. Shift swaps Raise and Lower for a new stroke. Radius, strength, falloff and spacing persist as editor preferences. Strength is metres per stamp for Raise/Lower and a clamped blend fraction for Smooth/Flatten. Stamps are spaced by `Radius * Spacing`; holding still adds no stamps. Flatten picks its target elevation at gesture start. Smooth gathers the whole stamp's results before changing samples so traversal order cannot change its neighborhood inputs.

`TerrainData::RaycastHeightfield` picks canonical source triangles using a quad DDA, independently of collision and rendering. `BrushStroke` requires all source pages, modifies shared samples through `Heightfield::SetSample`, and returns one deduplicated before/after delta array. A stroke can span four tiles. The tool owns the mouse gesture so picking, marquee selection and transform gizmos do not also consume it. Release outside the image completes a stroke; Escape or application focus loss cancels it. Switching tools/documents, navigation, selection changes and Play finish it. Painting is disabled during Play and for unsupported transforms.

Each `TerrainDocument` owns an `UndoStack`, a mutable CPU field and an immutable preview. Undo/Redo/Save route to the document while its panel or active brush viewport has focus; scene operations keep their separate history. The panel's undo/redo buttons always target its document. A stroke is limited to one million changed samples. History has a conservative 64 MiB delta budget in addition to the stack's command cap; reaching the byte budget releases older history before recording the latest stroke.

Preview publication creates an immutable resident snapshot, at most ten times per second during a stroke and once on completion. `Terrain::SetEditorPreview` shares it with every instance referencing that asset while preserving the serialized asset path. Play uses that immutable authoring snapshot; authoring is disabled until Stop restores the scene. `TerrainData::UpdateResidentTerrain` compares the current samples against the previous snapshot. It rebuilds patches intersecting each tile's changed sample bounds plus a one-sample normal halo, and collision tiles whose heights changed. Unchanged patches/collision arrays are shared through immutable pointers. The comparison does not depend on dirty rectangles, so saving before the next preview cannot hide changes. A new identity or changed settings triggers a full preparation.

`RenderCore` preserves mesh commands and GPU buffers for shared patches, retiring commands before replacing changed geometry. `PhysicsCore` caches cooked meshes by immutable collision tile, allowing old/new snapshots and multiple instances to share unchanged cooks. Instance shapes still rebuild together at the normal physics synchronization boundary; cooking an unchanged tile is avoided. The panel reports patch and collision-tile rebuild counts from the last CPU preparation. Canonical heightfields are copied on the editor thread when a preview worker becomes available. Comparison and changed geometry preparation run on that worker; source-page copy-on-write remains future work.

Brush Radius, Strength, Falloff and Spacing changes participate in the focused terrain's undo/redo history alongside strokes. A complete drag or committed numeric edit creates one command. Undo/redo updates the stored editor preference and the visible control. These commands return `false` from `UndoCommand::AffectsSavedState`, so adjusting or undoing a brush does not dirty terrain source heights, create recovery snapshots, or move the height save point. With no terrain open, the panel keeps a temporary tool history. Reopening/reverting a terrain resets its document history as before.

**Save Terrain** saves only the active asset; **Save All Terrains** saves all dirty terrain documents. **File > Save All** saves those documents and the scene. New/Open Scene and Quit check terrain dirtiness before the normal scene prompt. Closing the panel preserves its open documents; their unsaved state still participates in these prompts. **Revert from Disk** confirms discarding the active document. **Save Copy** creates a separate asset identity without rebinding scene instances; **Make Unique** also rebinds the selected instance, as an undoable scene edit. Other instances keep their original source and history. Terrain autosave/recovery is described below. Source asset operations in the browser are described below.

`TerrainData::SaveSource` writes all source pages to a fresh `<Name>.terrain-data/<generation>/` directory, then stages a neighboring manifest and atomically replaces the `.terrain` file. Windows uses `MoveFileExW`; macOS/Linux use same-directory rename. Serialization/write/publication failure removes the incomplete generation and leaves the previous manifest and pages intact. Successful saves retain previous generations; compaction is not implemented. The document checks the expected manifest text before staging and immediately before publishing to detect external manifest changes. This is an application-level publication guarantee, not a power-loss durability guarantee or a lock against concurrent external writers. Reopen validates every page and shared border before publishing a new preview.

## RAW heightmap exchange

Use the toolbar's Import/Export icons, the Tiles workspace's **Heightmap** / **Export** buttons, or the **Import Terrain Heightmap...** / **Export Terrain Heightmap...** command-palette actions. Import creates a new terrain asset; it does not overwrite the current document. New Terrain's **Import RAW heightmap** checkbox switches between flat creation and file import. An absolute RAW source path can be entered directly; Browse uses the project's asset picker. Reimport recipes and resampling are not implemented.

`TerrainData::RawHeightmap` declares sample width/height, `HeightEncoding::UInt16` or `Float32`, byte order, Z-row orientation, physical offset and scale. Width and height must equal `TilesX * TileQuads + 1` and `TilesZ * TileQuads + 1`. All bytes must be present, with no extra header or trailing bytes. The first file column maps to minimum terrain X. The first row maps to minimum Z, or maximum Z with **Flip Z rows**. Signed source tile coordinates do not change file ordering.

UInt16 import computes `Offset + (raw / 65535) * Scale`; Float32 import computes `Offset + raw * Scale`. Export applies the inverse. The default UInt16 mapping uses the physical height range; Float32 defaults to metres (offset 0, scale 1). Nonfinite values, zero scale, mismatched dimensions, missing source pages, heights outside the configured terrain range, and unrepresentable export values fail explicitly. Source pages stay Float32, and shared borders decode from identical RAW samples. No texture/color import path is involved.

UInt16 export rounds to nearest, introducing up to `abs(Scale) / (2 * 65535)` metres of quantization error, plus Float32 decode rounding. Float32 preserves source samples exactly with the default metre mapping. RAW adapters cap individual files at 64 MiB; the editor's one-million-stored-sample creation cap also applies to imported assets. The export dialog accepts `.raw`, `.r16`, `.r32`, `.f32`, `.h16` or `.bin`; the encoding controls determine the bytes, not the extension. RAW files contain samples only, so record dimensions and format settings when exchanging them with other tools.


## Terrain autosave and recovery

Havana saves dirty terrain documents under the project's `.tmp/Autosave/Terrain/` directory. **Autosave terrain** in Asset & Build enables/disables automatic snapshots; the global `Autosave.IntervalSeconds` preference sets the interval (120 seconds by default, zero disables automatic saves). Snapshots continue while the panel is closed. **Save Recovery Now** and the **Save Terrain Recovery Now** command take a manual snapshot. `TerrainWidget::PrepareForPlay` finishes active strokes and captures enabled recovery snapshots before `EditorApp::Play` starts simulation. Timed snapshots skip an active gesture and retry after release; they never store a partially captured stroke. Autosave pauses during Play.

The **Recovery** button in Asset & Build and **Terrain Recovery...** in the command palette open the recovery manager. On startup, pending terrain snapshots prompt after the scene recovery prompt. The manager lists source paths, UTC timestamps and invalid-record errors. **Restore** opens the snapshot as dirty authoring data with a fresh undo history and publishes its immutable preview to matching instances. It leaves the saved source untouched. Restoring over an already dirty document is rejected; preserve that work with Save/Save Copy or revert it first. **Later** keeps snapshots for another session. **Discard...** confirms deleting only the chosen snapshot; open document edits remain available and can be backed up again.

`TerrainData::RecoveryInfo` retains the original asset path/GUID, save time and exact base manifest. A `.terrain-recovery` file combines bounded JSON metadata with a full Float32 cooked heightfield. Both sections have checksums. Metadata inspection reads only the header/metadata; restoring validates the complete payload, shared borders, identity and settings before changing the document. Version 1 limits metadata to 8 MiB and payloads to 128 MiB. File writes stage beside the destination and atomically replace the previous snapshot using the same platform publication policy as source/RAW saves. Snapshots are self-contained and remain usable if the original source pages are missing. Failed or corrupt restores retain both the snapshot and current authoring state.

Filenames include asset and editor-session identifiers, so separate sessions do not overwrite each other's snapshots. Saving/reverting a document or undoing it back to its save point removes its owned/consumed snapshots. Unresolved snapshots from earlier sessions remain until the user restores or discards them. Restored documents retain the original manifest as the source save precondition; `TerrainDocument::CheckSourceIdentity` also checks the `.meta` GUID. External source edits or identity changes reject Save while keeping the recovered data dirty. **Save Copy** rescues that data into a new independent source asset. Force-exiting the editor keeps dirty terrain recovery files.

Recovery publication remains on the editor thread. Incremental preview preparation runs on an owned document worker as described below. Recovery captures heights and source provenance, not the prior undo command history or editor selection. Scene recovery remains separate and restores scene references. Unattended runs do not scan/write the user's recovery directory; tests explicitly configure `.tmp/Tests/` storage. The paired `../Assets/Scenes/Tests/TerrainRecovery01Write.edscript` and `../Assets/Scenes/Tests/TerrainRecovery02Restore.edscript` run in separate editor processes and verify timed saves, cancellation, clean undo cleanup, Play/Stop, restore, source conflicts and saving a recovered copy. Run them together with `RunEditorFlows.py --only TerrainRecovery`.


## Terrain asset operations

The asset browser's **Duplicate**, **Rename**, drag-to-folder move, and **Delete** now handle `.terrain` data and metadata together. Duplicate copies the saved source with a fresh manifest/metadata GUID and an independent generation of height pages. It leaves unsaved authoring buffers alone; **Save Copy** and **Make Unique** use the current authoring heights. Browser rename/move preserves the effective `.meta` GUID (or the manifest GUID when no sidecar exists) and publishes all current source pages under the destination's `<Name>.terrain-data/<generation>/` directory. Custom metadata fields are retained. Invalid sources/metadata, occupied destinations/sidecars and write failures reject the operation.

`TerrainData::TransferSource` stages a complete source and metadata in a private directory beside the destination. It publishes the height generation, then metadata, then the manifest; move retires the original manifest and metadata only after destination publication. It rechecks source text/metadata before publishing and retiring. Failure rolls back files owned by this operation and leaves the original readable; if an I/O failure prevents rollback, it retains the complete destination and reports its location. This is a staged application operation, not a concurrent-writer lock or a multi-file crash/power-loss transaction. Transfers currently decode/rewrite the full saved heightfield on the editor thread.

Previous source generations remain at their existing locations because another manifest or retained history may reference them. This matches the source-saving retention policy; compaction remains future work. The browser hides `.terrain-data` directories and `.thp` page files from ordinary listings/searches so they are handled through their source asset. Folder moves keep their relative layout and notify open terrain documents. Case-only renames on a case-insensitive filesystem may require an intermediate name.

Open documents follow source/folder moves with their dirty heights, undo history and immutable previews intact. Scene instances update their paths and mark the scene dirty; saved scenes/prefabs follow the GUID through the asset database when next loaded. Undo that restores a former terrain path resolves to its current shared preview. Pending recovery records are updated to the new source path, and matching base manifests are updated to the destination publication. Existing external-save conflicts remain conflicts. Enabled recovery snapshots refresh after a move. If a recovery record cannot be migrated, the original is retained and the panel reports the error.

**Delete** uses the existing confirmation dialog and moves a terrain into a unique folder under `.tmp/Trash/`, including an independent saved generation and sidecar. The trashed terrain is readable without its old location. Assets/folders containing open dirty terrain documents are rejected until those heights are saved or reverted; the browser shows the reason inline. Clean matching documents close, previews/cache records retire, and scene references remain at their original path so deletion is visible. Old source generations retain the same history policy above. Asset file operations are not entries in the scene/terrain undo stacks; Trash is the retained copy.

## Streamed runtime terrain (versions 2 and 3)

Use **Terrain > Tiles > Cook**, **Asset & Build > Build**, or **Cook Streamed Terrain...** in the command palette. Choose a `.terrainc` destination and a coverage level. **Page coverage (version 3)** is enabled by default; disable it to cook the version 2 resident overview. The worker cooks an immutable copy of current authoring heights, including unsaved strokes, and atomically publishes a neighboring staged file. Existing files require the dialog's replacement checkbox. Cooking neither changes the source nor rebinds scene instances. Assign the cooked file to a Terrain component to preview runtime streaming; the source document stays resident for authoring.

Version 2 archives begin with `MTS2`, a 104-byte little-endian header, a checksummed 40-byte record per tile, then checksummed coarse coverage and independent detail blocks. Detail blocks contain Float32 canonical heights and canonical normals, so reading one tile does not synchronously load its neighbors. The directory records signed coordinates, offsets, exact sizes, checksums and height bounds. Opening reads only header, directory and coverage. Every detail read checks the opened file's size/header identity and its block checksum; an external replacement requires Reload Terrain. Version 1 `MTRN` cooked assets and source `.terrain` files retain their resident loading behavior.

Coverage has the same patch footprints as canonical data, with fewer stored vertices. Its geometric errors and bounds still refer to the canonical heightfield. The LOD selector propagates minimum available levels across neighbors before error selection, coarsening a transition band beside missing detail to preserve 2:1 strides. Requested error may exceed the pixel budget while detail is unavailable. Forward, shadows, picking and wireframe continue to share actual uploaded topology. Initial coverage finishes uploading before the terrain first draws. Detail/eviction uploads replace individual patches while prior coverage remains available; archive revisions start a fresh coverage upload.

Terrain inspector settings control detail distance, the version 3 coverage horizon, collision safety distance, CPU/GPU/collision budgets, upload KiB per frame and upload milliseconds. The cache merges demands from instances of an archive in one world, uses the smallest configured budgets, and reserves conservatively for per-instance GPU/shape overlap. Camera requests compete by distance after required collision. Characters and non-static rigidbodies request collision independently of cameras, expanded for compound collider size, horizontal velocity and pending movement. Physics stepping waits while required canonical pages or collision cooks are unavailable, including after teleport; other script/game updates continue. Box3D preparation runs on an owned worker and shape swaps occur at the normal physics synchronization boundary.

Reservations include coverage, decoded/prepared CPU data, upload/cook overlap, pending requests and retiring consumers. Query snapshots, active patch geometry and collision cooks retain cache pins. Optional detail leaves after an unload delay or earlier under pressure; its reservation releases after consumers retire. GPU detail can return to coverage independently while an off-camera actor retains the same tile’s canonical query and collision data. A failed detail request keeps valid coverage and records its error without a per-frame retry loop. Reload Terrain retries with a new archive/cache generation. Nonresident canonical queries report Pending or Unavailable and never substitute coarse heights or start synchronous I/O. Deterministic `--frame-time` runs explicitly drain requested CPU work; normal play only polls completions.

**Inspect > Residency** colors uploaded detail green and coverage blue and shows tile counts, reserved bytes, requests, eviction/cancellation counts, pressure and page readiness. These are conservative reservations rather than exact backend allocation counters. Source authoring documents have independent residency. Component ceilings apply per archive/cache; Project Settings adds one shared allowance across all active and retiring streamed assets in each world.

**Project Settings > Terrain** controls shared CPU, GPU and collision MiB plus concurrent coverage/detail loads (defaults 256 / 128 / 512 MiB and 2 loads). These persist under `TerrainStreaming` in `Assets/Config/ProjectSettings.json`. Inspect shows both selected-asset and aggregate world reservations. The coordinator ranks all assets together: required collision first, then version 3 coverage, then optional detail, each ordered by distance with stable asset/path/tile tie breaks. Per-asset ceilings still apply. Optional demand that loses its allowance retires immediately under pressure. Each admission checks the live reservations of the other assets, so a new priority cannot reuse memory still held by their pending requests, query snapshots, draw retirement or collision shapes. Removed/disabled instances release their component snapshot; the cache remains charged until its consumers and owned work retire. Whole-instance draw removal also retains patch pins through deferred GPU buffer release. Peak instance reservations are retained until that cache retires, covering overlap when instances disappear.

Lowering a limit can leave existing pinned reservations above the new limit; Inspect reports the overage while new allocations wait. Version 2 coarse coverage remains a fixed load-time cost; version 3 opens only metadata. Opening archives happens through the resource loader before world admission, and archive metadata/legacy overviews can remain in the resource cache. If those fixed costs alone exceed the shared allowance, terrain drawing/required collision readiness is held and the panel asks for larger limits or smaller/coarser data. Shared budgets govern streamed world residency, not all process allocations or resident authoring/source assets. Version 3 page loads are admitted by the same world coordinator as canonical detail.

Version 2 limits storage tiles to 256 quads, the directory to 65,536 tiles/patches, and the global coarse payload to 64 MiB. Version 3 keeps the 256-quad tile and 65,536-tile directory limits, bounds each individual coverage read to 64 MiB, and removes the global resident-patch limit. Multi-level coarse hierarchies, directory paging, streamed authoring and navigation residency remain follow-ups. Lossless version 5 page compression is described below. Coarse coverage must fit the configured budgets. Individual uploads/cooks are bounded patch/tile units; the time budget cannot preempt an operation already started. Full detail vertex buffers are released on eviction, while shared stitch patterns remain bounded by the configured patch resolutions.

### Paged visual coverage (version 3)

Version 3 archives start with `MTS3` and the same 104-byte little-endian header size. A checksummed directory has a 64-byte record per tile, containing separate offsets, sizes and checksums for coarse coverage and canonical detail. Each tile's coverage block precedes its detail block. The old global coverage size/hash header fields are reserved as zero. Opening reads the header and directory and computes full asset bounds; it allocates no patch geometry and reads no coverage/detail payload. `ReadStreamCoverage` validates one page's identity, checksum, finite normals/heights, bounds and index data. Canonical reads remain independent of coarse-page availability, including a corrupt coarse page.

`CoverageDistance` defaults to 1,024 metres. Each rendering camera requests a clipped tile window around that horizon; detail distance is clipped to it. Coverage requests compete for shared CPU/GPU budgets after required collision and before optional detail. The admitted horizon may shrink under budget pressure. **Horizon ready** means that admitted CPU window is published; GPU uploads can still be finishing. Inspect reports coverage loads, evictions, pending/retiring pages and pressure. Disabling Stream Detail retains the coarse horizon, with canonical pages loaded only for required collision. Off-camera actors can keep canonical queries/collision while no visual patches cover them.

Coverage snapshots contain only window patches and their signed neighbor table. New coverage enters a window only when all its admitted pages are ready; unchanged overlap remains available. Pages outside the new horizon retire first, freeing their reservations after query/draw consumers release them. During teleport or severe pressure the visual window can temporarily be empty while new pages arrive. The renderer stages new windows within upload limits, reuses overlapping buffers, and retains the previous GPU window until the staged replacement is complete. Actual uploaded representations continue to use the same 2:1 balancing/stitching path as version 2. A failed coverage page records an error without per-frame retry; repair and Reload Terrain retry it. Failed canonical detail retains valid coarse coverage.

This is a finite visual horizon with fixed patch footprints. It does not keep a global distant overview, merge distant patches into hierarchical parents, or page the directory itself. Dataset metadata remains proportional to tile count; authoring documents remain fully resident. Runtime coverage/query/physics caches and pending/retiring representations are budgeted conservatively, rather than claiming an exact process-memory ceiling.

### Surface authoring

Open a source asset and choose **Terrain > Paint**. Select one of four palette entries, then use **Paint** or **Erase** in World View with the shared radius, strength, falloff and spacing controls. Strength is a blend fraction per distance-spaced stamp, clamped to one. Shift reverses paint/erase; Escape restores the source before the gesture. **Fill** replaces the entire terrain with the selected layer; **Clear** selects the first layer everywhere. Both are single undoable operations. **Edit selected layer** and **Material** open an Apply/Cancel dialog for its name, sRGB color tint, roughness/metallic factors, base-color/normal/packed ORM maps, tile size in metres, normal strength and normal Y flip. Texture fields accept project-relative paths, asset browsing and drag/drop; Clear removes an assignment. ORM channels are R occlusion, G roughness, B metallic. **Disable surface layers** restores component color/roughness and can be undone.

Painting and palette changes belong to the terrain asset document. Shared instances update together; scene history stays independent. One gesture creates one asset command, and the existing saved-state/history routing applies to fill, palette edits and enabling/disabling layers. Brush preferences retain their separate undo behavior. Saving, Save Copy, Make Unique, asset move/duplicate, and recovery snapshots preserve surface data. A no-op on an existing surface creates no new command.

A `Surface` has four named layers, normalized RGBA8 base weights and sparse overrides at signed global sample coordinates. Every stored weight vector sums to 255. Missing samples use the base weights, so whole-terrain fills do not allocate per-sample entries. Largest-remainder quantization preserves the sum; zero input selects layer zero. Erasing redistributes weight among the other layers proportionally; a pure selected layer transfers to layer zero (or layer one when erasing layer zero). Shared tile/patch boundaries have one authoritative weight value. Surface overrides are capped at one million samples; authoring remains fully resident. Preview publication uses immutable surface snapshots. History stores compact encoded before/after surfaces within the existing 64 MiB history accounting; even a one-million-sample command fits that budget.

Source manifests with a surface reference use **version 2** and add a portable relative `Surface` path. The referenced `Surface.tsurface` lives in the same uniquely published generation as the height pages. Height-only manifests/pages remain version 1. The companion starts with `MTSF` and a 24-byte little-endian header containing metadata length, override count and a 64-bit payload checksum. Version 1 companions contain colors/roughness. New writes use version 2, which adds texture references and shading/tiling parameters; the reader supplies defaults for version 1. Metadata is bounded to 32 KiB. JSON metadata holds four layer descriptors and base weights; each 20-byte record contains signed 64-bit X/Z coordinates and four weight bytes. Decoding validates lengths, checksums, bounds, uniqueness, colors/roughness and normalized weights before publishing any output. Manifest publication retains its external-save conflict check and atomic replacement.

Recovery retains the version 1 outer container. Painted snapshots use metadata version 2 with `HeightBytes`: a legacy Float32 height prefix followed by a complete surface companion. The payload checksum covers both sections. Recovery does not depend on source companion files still being available. Existing height-only snapshots remain readable.

`TerrainMaterial` blends colors in linear space and roughness through the existing PBR lighting path. Each patch has a full-resolution linear RGBA8 weight texture in stage zero, independent of its current geometric LOD. UVs map the first/last lattice samples to texel centers; matching edge samples and clamp sampling keep bilinear filtering consistent across patches. Painting reuses CPU patches, GPU vertex buffers and canonical collision data. Only changed weight textures are replaced. The material batch key includes layer values and the weight texture identity; lighting keeps stages 8–15. LOD/residency diagnostics override the painted colors.

This checkpoint supports resident `.terrain` sources in the editor and standalone game. Paged cooking now writes version 4 for painted sources, preserving the palette, map references and full-resolution weights. Legacy resident/version 2 cookers still reject layered sources while preserving the destination. Weight import/export and masks remain follow-ups. Future tool buttons remain visible in the panel.

### Textured surface layers

Texture coordinates repeat in terrain-local X/Z, with a per-layer **Tile size (metres)**. Translating a shared terrain instance preserves its texture phase. Shading blends base color in linear space, applies layer roughness/metallic factors to packed ORM channels, and transforms blended tangent-space normals through the terrain frame. Normal maps reconstruct Z from XY, support strength and Y flip, and use the same convention as Standard materials. Missing maps are white base/ORM and flat normals. Color tints default to the existing palette; choose white for an untinted base-color map. Alpha is opaque.

A path set shares one `TerrainTextureSet` across patches and instances; changing weights or shading factors does not repack maps. One owned process-wide worker handles decode, resize and semantic mip generation. Queued obsolete requests cancel, and promise-backed futures avoid waiting in render-frame destructors. Jobs own all their inputs and never touch the GPU; the queue joins its worker on shutdown. Complete packs upload on the main thread. Deterministic captures may wait for their pending pack. This resident authoring path is separate from streamed world residency/upload budgets.

The loader prefers a map's compiled `.dds` twin, falling back to its source image. Compiled-only maps work in standalone builds. Inputs must be ordinary 2D images up to 4096 pixels per axis and 128 MiB per file. Array layers resize to 512 square texels with area filtering on reduced axes and bilinear repeat filtering on enlarged axes. Base-color mips average in linear light and encode back to sRGB; normal mips average vectors and renormalize; ORM channels remain linear data. Paths are project-relative references. Moving a source terrain retains its texture references; texture reassignment updates references through the layer editor.

The material uses stages 0–3: the per-patch linear weight map, then base-color, normal and ORM packs. Stages 8–15 remain available for lighting. Texture-array support is checked through actual backend layer/size/sampler limits and RGBA8 texture validity. The array path uploads three four-layer mipmapped textures. The fallback uploads three 1024-square 2×2 atlases. Each atlas layer has independent repeat gutters at each usable mip; the shader calculates LOD from continuous UV derivatives before wrapping, then manually blends adjacent padded mip levels. The last usable mip contains a constant average per layer, and merged tail mips are never sampled. `--terrain-texture-atlas` forces the fallback for diagnostics. Unsupported backend limits leave color/roughness shading available with an inspectable error.

Texture file stamps are checked once per second per shared set, including source and compiled twins. A replacement prepares a complete new pack before publishing any texture. Corrupt/missing replacements retain the last valid GPU pack and report the error in the Paint panel; a subsequent file update retries. A failed first load displays layer colors until repaired. Material batch keys include packed texture identity, layer factors, tiling and terrain origin, as well as weight-map identity. Packed layer maps remain shared resident GPU resources. Their derived pixels now use the persistent cache described below.

### Streamed surface pages (version 4)

### Persistent packed texture cache

Terrain texture sets first look for a derived pack under `.tmp/Cache/TerrainTextures/`. A cold request fingerprints the selected image bytes, prepares the ordinary semantic mips, rechecks the source generation and atomically publishes a complete `.tpack` file. A subsequent editor/game process can load those packed pixels without decoding, resizing or filtering the source images again. The single owned packing worker performs fingerprinting, cache I/O, packing and cleanup; GPU creation still happens on the main thread. Queued obsolete requests cancel, and a generation that changes before upload is discarded.

The key includes the packing revision, array/atlas layout, cell resolution and the ordered twelve inputs' presence, byte length and content fingerprints. It follows the existing compiled `.dds` preference. Absolute source paths and timestamps are excluded from the identity, so relocated identical inputs reuse the same pack and changes with preserved timestamps invalidate a new request. Missing inputs and corrupt preferred compiled files still fail normally; an old cache never substitutes for unavailable source/compiled images. The live file watcher continues to use timestamps/sizes once per second. Layer colors, roughness/metallic factors, tiling and paint weights remain outside the pack key.

The version 1 `MTPK` container has a 64-byte little-endian header, fixed input identity and RGBA8 mip payloads in a deterministic order. The loader validates the format/packing versions, identity, layout, dimensions, exact expected byte count and header/payload checksums before publishing data. Shapes and allocations come from the requested supported layout/resolution, not untrusted cache fields; a production pack is bounded below 17 MiB. Readers see a complete previous or replacement file. Damaged, incompatible or truncated entries rebuild from images. Cache read/write failures are nonfatal, including a read-only install: rendering uses freshly packed data and retains its normal source/GPU failure behavior.

The default disk target is 512 MiB. Successful reads refresh entry age; publication/hits remove the oldest recognized `.tpack` files first, preserving the current entry. Cleanup ignores other files and is best effort when concurrent processes or permissions prevent deletion. Temporary writes use unique neighboring names and clean up on failure. This disk target is independent of terrain page budgets; layer texture packs remain shared resident GPU resources.

`--terrain-texture-cache-dir <path>` selects another directory. `--no-terrain-texture-cache` bypasses it. `--terrain-texture-cache-info` logs hit/store/bypass results and nonfatal cache diagnostics after a complete GPU upload. Deleting the derived directory is safe; source assets and their compiled twins remain authoritative.

## Navigation baking

Add a `NavMeshSurface` and bake through its inspector or Navigation actions. Terrain participates once in Physics Colliders, Render Meshes and Both collection modes; Physics Colliders omits terrain with collision disabled. Layers, collection bounds, inherited translation, modifiers and moving-body exclusions apply. Unsupported rotation/scale and unavailable sources report an error while keeping the previous bake.

Navigation always uses canonical sample triangles. The main thread captures immutable sources; the bake worker reads selected version 2/3/4/5 archive detail pages independently of visual coverage, detail residency and physics demand. Bounds include a Recast border halo. Reads validate the archive generation and checksums, build no render/collision data, and do not populate the runtime tile cache. At most four million terrain triangles are accepted per bake; narrow the collection volume or split surfaces for larger terrain.

Height edits mark the surface stale, and undo restores its prior geometry hash. Painting, texture changes and LOD selection preserve the bake. Source or settings changes during a running bake discard that result before file publication. `BakeOnLoad` retries pending terrain metadata, including in standalone games. Runtime carving uses the captured bake source and settings; first carving of a file-loaded mesh verifies source identity. See [Navigation](Navigation.md#terrain-sources) for details. Terrain rebakes remain explicit full-surface operations; runtime navmesh tile streaming is a later milestone.


## Optional actor look-ahead

Required collision demand covers actor extents, a sample border, the actual next fixed step and any explicit pending movement. `PhysicsCore` forwards its fixed timestep before synchronizing terrain, including custom step sizes. A larger future region is optional: `CollisionPrefetchSeconds` defaults to 0.5 seconds and accepts 0–2 seconds; zero disables look-ahead. Character demand includes current velocity and movement intent, and rigidbody demand uses horizontal velocity. Vertical falling speed does not widen the region.

The world scheduler admits required collision first, coarse visual coverage next, then canonical prefetch and optional visual detail. CPU look-ahead shares the existing per-asset/world limits, worker limit, checksums, cancellation, retirement pins and eviction policy. Prefetched pages populate canonical height queries, but request no GPU detail or live collision shapes. When a page becomes required, its prepared CPU data is reused without another archive read; Box3D collision cooking and publication still use the required-ground readiness barrier.

A corrupt optional page records an error without pausing physics or retrying each frame. If it later becomes required, readiness waits until the asset is repaired and reloaded. A budget-deferred optional request also leaves physics running. Teleports and explicit sweeps still wait when their required region is absent. Inspect shows look-ahead CPU pages and pending requests separately from visual detail and required collision. When a shrinking visual window reuses patches and demotes detail, shared draw command slots remain owned by the previous window until its retirement; this prevents duplicate slot release and missing patches.

## Lossless streamed page compression (version 5)

**Cook / Build → Page coverage → Compress pages** writes `MTS5`, version 5. Compression defaults on in the cook dialog when paging is enabled; unchecking it retains the existing version 3 height-only / version 4 painted formats. Disabling paging retains the version 2 resident overview. Source assets and previously cooked versions remain readable.

Version 5 retains the 104-byte header and 64-byte tile directory. The bounded, independently checksummed palette is optional: height-only archives have none. Opening reads only the header, directory and palette. Coverage and canonical height/normal blocks remain independently requested and checked; navigation reads only canonical blocks. Compression runs in the cook worker and decompression in the existing owned page/navigation workers. Normal frame preparation does no blocking decode or file I/O.

Each block has an eight-byte little-endian envelope: codec and decoded length, followed by the stored payload. Codec 0 stores raw bytes. Codecs 1/2/3 transpose 4/8/16-byte records into byte planes and encode bounded literal/run packets. Controls 0–127 introduce 1–128 literal bytes; controls 128–255 repeat the next byte 3–130 times. The cooker chooses the smallest supported layout, falling back to raw when compression would grow the payload. Raw fallback adds only the fixed envelope. The directory stores actual lengths/offsets and checksums of decoded bytes; content revisions retain the logical height/paint identity independently of the encoding.

Before allocation, readers derive exact decoded lengths from validated settings, coverage level and palette presence. Envelope lengths must match those derived sizes. Stored lengths are bounded by raw length plus eight bytes, decoded blocks by 64 MiB; unknown codecs, invalid layouts, overrun/underrun, truncated packets, trailing bytes and checksum failures reject the page without publishing partial output. Header and directory checksums, exact contiguous ranges, file length and immutable generation checks still apply. A corrupt coverage page does not invalidate another page or canonical collision. Failed cooks preserve the previous file through the existing staged atomic publication.

CPU reservations include overlapping stored/decoded buffers using the full raw size, regardless of the achieved ratio. GPU/collision costs and retirement pins retain their existing policies. Compressed file size does not increase decoded residency allowances. Inspect shows successful page payload bytes read versus decoded bytes (including raw envelopes, excluding metadata/header rereads, failures and cancelled completions). These are cumulative successful publication counters rather than a process-wide I/O meter.

`TerrainCompressionTests.cpp` covers arbitrary bit patterns/raw fallback, malformed blocks, exact legacy geometry/normals/LOD/weights/collision parity across every coverage level, isolated corruption, failed publication, generation replacement and cache promotion/pin accounting. `../Assets/Scenes/Tests/TerrainCompressedFlows.edscript` exercises 1,681 painted tiles within a shared 1 MiB budget, compressed payload counters, movement, coarse-only rendering, teleport, canonical raycasts and Play/Stop.

## Hierarchical distant coverage (version 6)

**Cook / Build → Hierarchical distant coverage** opts into `MTS6`, version 6. This enables paged, compressed coverage and requires at least two stored quads per patch. Existing source assets and versions 2–5 remain supported. The cook dialog clamps the coverage level to the hierarchy's supported range; the default cook remains version 5.

The hierarchy is a dyadic forest anchored at `MinTile`, with no padded tiles outside a rectangular terrain. Every node covers a square of `2^Level` source tiles, using the same patch count and stored vertex resolution as a leaf page. Distant parents therefore cover more ground with fewer patches. Leaves keep their canonical tile identities and page weights. Parents sample canonical heights and the canonical normal field at larger strides. Their bounds and LOD error envelopes include every underlying canonical height, including peaks between stored vertices. Parent weight textures point-sample paint at the larger footprint; they are a distant approximation. Leaf weight textures remain exact. Metre-based material repeats retain their world phase across different footprints.

Version 6 has a 128-byte header, the existing 64-byte leaf directory, and a separately checksummed 64-byte node directory. Node records store signed origin, level, parent/children, payload range/checksum, and canonical height bounds. Readers regenerate the expected topology and compare every link/address, duplicate leaf range and bound before accepting it. Counts, contiguous ranges, file length and decoded sizes are validated before payload allocation. Node pages use the version 5 compression envelope and immutable-generation checks. Limits remain 65,536 source tiles and 64 MiB per decoded page; the total decoded resident root payload is also limited to 64 MiB. An unsupported cook fails without replacing the previous archive.

Opening version 6 reads metadata, palette and a balanced resident root forest on the resource worker. Unlike versions 3–5, it deliberately loads these required coarse pages at open time. The roots cover the entire terrain and are charged as fixed CPU/GPU reservations. A corrupt root rejects the replacement archive; a corrupt optional parent fails independently and retains valid coarse coverage without a per-frame retry loop. Normal frame preparation does no blocking terrain reads/decompression.

Coverage selection merges local views from every participating camera and shared terrain instance. This first hierarchy slice uses distance bands inside `CoverageDistance`, with leaf demand around `StreamDistance`; projected error still selects mesh LOD within available pages. The usual cut limit is 1,024 nodes (or the root count when larger), independent of how many leaves a square world contains. Rectangular/thin worlds can require more roots, subject to the decoded-root limit. Ancestors remain requested as fallbacks. Shared world admission reserves complete sibling groups, parents before descendants, after required canonical collision. Optional refinements obey per-asset and world CPU/GPU allowances, the concurrent-load cap, upload limits and retirement charges. Insufficient budgets retain roots or a coarser admitted cut.

Publication replaces a parent only after all four children are ready, and coarsens incomplete boundaries to a ready ancestor. Every published cut covers the complete terrain exactly once and keeps neighboring footprints within a factor of two. A compact adjacency list includes both small patches along a larger neighbor's edge; LOD balancing and stitched indices visit every link. This also handles canonical detail next to coarse pages. The renderer stages geometry and seam topology, retains the previous complete window while uploads finish, and exposes a new window only once all its meshes are usable. Cache and draw pins keep previous pages charged through deferred GPU retirement.

Hierarchy pages are exclusively visual. Canonical height queries, collision readiness, movement prefetch and navigation reads continue to use independent source-tile blocks. A visible parent never makes missing collision or query data ready. Teleports retain the existing collision barrier. Navigation can read version 6 canonical blocks without loading visual refinements.

## Background authoring previews

Sculpt, paint, undo and redo request incremental CPU previews on one owned worker per open terrain document. A busy document coalesces changes without queuing field copies: once its current job finishes or cancels, it captures the newest canonical field. Workers own immutable field/previous-preview snapshots and touch no editor, world, renderer or physics state. Patch/LOD preparation checks cancellation between patches and rows. The panel pumps all documents even while closed, and publishes complete snapshots on the editor thread. Unchanged patches and collision tiles retain their shared identities.

Publication checks the document generation, asset GUID and canonical revision. Reload, recovery restore and replacement invalidate the generation even if the source's local revision counter repeats. Superseded successes and failures are discarded. Current failures preserve the previous usable preview, show an error and wait for a changed source or **Retry preview**; normal frame polling does not retry them. Document destruction cancels and joins its owned work.

Canonical edits/history remain immediate. Save, Save Copy and recovery serialize canonical data independently of preview lag, including when a save clears dirty rectangles during a build. They retain existing source conflict and atomic publication rules. Play finishes strokes and waits for each document's latest preview before starting simulation; a failed preparation leaves the editor stopped. Explicit automation uses `terrain-preview-wait` at readiness boundaries.

This moves repeated sample comparison, patch geometry/LOD construction and collision-array preparation out of the brush loop. Capturing a field still copies its canonical heights on the editor thread. Initial open/create/restore preparation, source file operations and recovery writes remain synchronous; authoring still uses resident source pages. This is separate from runtime page streaming.

Runtime source readers keep their existing unrestricted default; cooked runtime streaming is independent of this editor limit.
